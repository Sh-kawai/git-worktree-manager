# 厳格運用の方針

- 編集前に変更方針を提示し、ユーザーの明示的な承認を得る。
- 構成確認、検索、読み取り、Git 状態確認、および通常のローカル検証は、編集の承認前でも追加承認なしで実行してよい。
- 通常のローカル検証には、有料 API や外部への更新・送信を伴わないテスト、リンター、型チェック、構文チェックと、それらに必要な一時ファイル・キャッシュ・検証出力の生成を含む。書き込み先は許可された作業領域または専用キャッシュに限定し、共有実データや保護対象は変更しない。
- 検証前に実行対象と設定を確認する。有料 API 呼び出し、外部への更新・送信、デプロイ、破壊的操作、保護対象の変更を伴う場合は、対象と影響を示して明示承認を得る。外部 API 呼び出しの有無が不明な場合も、確認できるまで実行を止める。
- 実 API を使うテストは、通常の検証では既存の無効化設定やモックを使って除外する。依存関係のダウンロードは別途扱い、既存の依存関係で実行できる検証を優先する。

- 承認済みの実装・検証に必要なローカルGit操作は、親のGit運用ガイドで定めた範囲で追加確認なしに行える。コミット・rebaseは対象一覧とメッセージ等を提示して明示承認を得る。push・PR作成・公開・削除・共有履歴変更は対象を特定した明示依頼を必要とする。
- `git reset --hard`、`git checkout --`、`rm`などの破壊的操作は、対象と影響を示して明示承認を得てから行う。
