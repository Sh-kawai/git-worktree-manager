# worktree 管理ガイド

worktree の作成、配置、共有リンク、親リポジトリの Git 管理範囲を扱う場合だけ参照するガイドです。

## 管理境界

親リポジトリが管理するのは、worktree の配置、共有リンク設定、補助スクリプト、Codex 用の管理規則です。各 worktree の仕様、業務ルール、実装は管理対象に含めません。

Git の追跡対象と除外対象は `.gitignore` を正本とし、利用者向けの概要は `README.md` を参照します。`.worktree-shared.toml` はローカル設定、`.worktree-shared.sample.toml` は共有用ひな形として扱います。

## worktree の作成

1. 親リポジトリのルートと対象ブランチを確認する。
2. `scripts/new-worktree.sh <branch>` を使って作業用 worktree を作成する。
3. 作成先が `git-worktree/<branch-name>` であることを確認する。
4. 共有リンクの設定結果と、既存ファイルが上書きされていないことを確認する。

対象worktree、作成元、作成先、共有リンクの状態を確認できた時点で作成作業を完了とします。

## 共有リンク

既存 worktree へ共有リンクを適用する場合は、`scripts/setup-worktree-shared.sh <worktree-path>` を使用します。リンク先に通常ファイルまたは通常ディレクトリが存在する場合は上書きせず、対象と移動方針をユーザーへ確認します。

worktree 内の文書やコードでは、共有データの物理パスではなく、その worktree 内のシンボリックリンクを起点とするパスを使用します。

## 変更時の検証

worktree の配置や管理スクリプトを変更した場合は、次を確認します。

- `AGENTS.md`、管理スクリプト、設定例に古い配置パスが残っていない。
- `main` と `develop` が参照用として保護されている。
- `.gitignore` の追跡境界が意図せず広がっていない。
- 各 worktree 内の成果物が親リポジトリの外部パスに依存していない。

すべての確認結果と未確認事項を報告した時点で変更作業を完了とします。
